THE DECISION

Use a modular monolith with a typed creative planner and a durable render workflow. Video frames come from your images, typography, and compositing—not a paid video model. Presets work without any network calls. Optional hosted text or vision assistance has separate provider quotas; it is not assumed to be free. All future components below are explicitly marked PROPOSED.

01 / PLAN → VALIDATE → EXECUTE

Typed creative planning

Ask a model for a small ScenePlan object, not an FFmpeg command. Validate asset IDs, template version, duration, motion range, and overlay positions in Python.

“Make it feel energetic” → a permitted zoom curve and a bold typography template. Unknown motion types are rejected.

02 / CHECKPOINTED STATE GRAPH

Durable workflows

Save a run’s state between planning, preview, review, render, and quality checks. Resume the same run after a restart rather than starting the entire pipeline again.

A completed plan remains saved while you approve the preview. Use persistent checkpoints; RAM-only state cannot survive a restart.

03 / A DECISION BOUNDARY

Human review checkpoints

Pause before committing a creative plan to a full render. You can adjust wording, crop, and timing. Approve a particular plan revision, so edits invalidate old approval.

Approve revision 3. Editing its headline creates revision 4 and returns the workflow to preview.

04 / CAPABILITIES, NOT BRAND NAMES

Provider boundaries

Use TextPlanner and optional VisionReviewer interfaces. Groq or NVIDIA may assist planning when account access permits. The renderer is always local FFmpeg.

If a hosted quota is exhausted, fall back to a deterministic template. Never switch to a paid service automatically.

05 / CONTENT-ADDRESSED WORK

Versioned, repeatable renders

Hash the source artwork, overlay, validated plan, template version, and renderer version. Reuse matching outputs. Record the model response used to produce a plan.

Retry after a dropped connection → the same saved job. A new asset or template produces a new render key.

06 / MEASURE THE OUTPUT

Evidence & evaluation

Check codec, dimensions, duration, file integrity, and text bounds deterministically. Keep representative frames for human review. A vision model may flag visual concerns, but cannot certify quality.

Store a timestamped frame showing clipped text. A bounded revision can fix placement; no endless critic–generator loop.

    04 / THE CONTRACT IS THE ARCHITECTURE

    Make creativity executable.

    The following schema is a proposed v2 contract. The current API accepts ClipSpec with a single motion preset; it does not yet interpret an AI-generated scene plan.

    A plan is data, not shell code.

    The model selects from a small vocabulary of motion and typography rules. Your compiler translates that vocabulary into trusted FFmpeg arguments. Never execute command text returned by a model.

    • Asset identity: only known uploaded asset IDs; do not let a model choose arbitrary URLs or filesystem paths.
    • Provenance: record the asset hash, prompt template, model ID, and plan revision.
    • Render policy: local renderer only, duration and pixel limits, one active CPU render.
    • Reproducibility: reuse a stored plan and pin the template and renderer versions. Model generation itself is not assumed deterministic.
    • Approval: bind the review decision to the exact plan hash.

    Example: the phrase “subtle push-in” becomes a scale range of 1.00 → 1.08. FFmpeg then computes each frame. The AI never invents pixels for a new object.

    06 / AN ARCHITECTURE YOU CAN GROW INTO

    Build one new concept at a time.

    Modern does not require a large cluster. These phases deliberately preserve a useful workflow when every hosted AI service is unavailable.

    PHASE 0 · BUILT

    Local motion studio

    • Browser Canvas preview and editable overlays.
    • FastAPI + SQLite job snapshots.
    • Single in-process queue and CPU FFmpeg.
    • Persistent media volume and MP4 downloads.
    • Paid video generation removed; external video mode is rejected.

    Learn: API contracts, asynchronous work, media encoding, container persistence.

    PHASE 1 · RECOMMENDED NEXT

    AI-directed motion graphics

    • Versioned template registry and ScenePlan schema.
    • Optional typed text planner; preset fallback.
    • LangGraph with persistent SQLite checkpoints for this single-instance deployment.
    • Preview/review checkpoint bound to a plan hash.
    • Safe render compiler, atomic outputs, quality records.

    Learn: structured output, bounded agent tools, durable state, evaluation.

    PHASE 2 · WHEN LOAD REQUIRES IT

    Separate the worker

    • Keep the API responsive while the CPU worker renders.
    • Persistent job claims, leases, retry counters, and queue limits.
    • Move SQLite to Postgres when concurrency justifies it; add object storage when local disk is insufficient.
    • Choose one operational workflow owner; consider Temporal for a distributed service.
    • Add user identity and per-user media access before opening the service to others.

    Learn: leases, idempotency, backpressure, ownership, and measured scaling.

    Small-instance deployment: start with the existing single container at port 4173 and a persistent /app/data volume. Its configured limits are 1.5 CPU and 768 MB; these are settings, not benchmarked capacity guarantees. Render one clip at a time and measure peak memory. Hosted inference is optional. No GPU model server, vector database, or resident tracing collector is required.
